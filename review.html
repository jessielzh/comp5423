L1A Inside the ModelA language model predicts the next token; everything else in the course is how that is built and used.
The model sees tokens, not letters or words
  • A tokenizer cuts text into tokens; each token has an ID, a row number in the vocabulary. L1A 2:1 L1A 3:1
  • The vocabulary is a design choice, made by an algorithm such as BPE. L1A 2:3
An embedding turns each token into a learned vector
  • The tokenizer is an algorithm; the embedding is learned in training. L1A 3:2 L1A 3:3
  • One token, one vector: context must do the rest, through attention. L1A 3:4 L1A 4:1
Three stages of training
  • Pretraining (next token, web text, most expensive) → supervised fine-tuning (how to answer) → alignment (which answer people prefer). L1A 5:1 L1A 5:5
L1B Around the ModelAlmost all the work is around the model: prompting, RAG, fine-tuning, agents, evaluation, safety.
Three strategies fix different problems
  • Prompting is free and comes first. RAG changes what the model knows; fine-tuning changes how it behaves. L1B 2:2 L1B 4:3
  • RAG: chunk → embed → store, then embed → retrieve → assemble → generate. L1B 3:2
An agent is a model, tools and a loop
  • The model decides when to call a tool, from the tool's description in words. L1B 5:2
Shipping it
  • Evaluation is a fixed test set with a score you can compute, run on every change. L1B 6:2
  • Guardrails live around the model, not inside it. L1B 7:2
L2A Tokenization and EmbeddingText becomes vectors; a loss says how wrong they are; small steps fix them.
BPE: merge the commonest neighboring pair, repeat
  • Training: start from single bytes, join the most frequent pair, add it to the vocabulary, until the size you chose. L2A 2:1
  • Encoding new text uses the frozen merges. Starting from bytes means any text can be encoded. L2A 2:2 L2A 2:5
  • Common words stay whole; rare words break into pieces. L2A 1:2 L2A 2:4
The embedding matrix is a lookup table
  • E is V×d; a token ID picks a row. E is the model's first layer, filled in by training. L2A 3:1
  • Similar words have vectors that point the same way: a large dot product. L2A 3:2
word2vec learns vectors by predicting neighbors
  • A word is represented by its context; predicting it beats counting it. L2A 3:3 L2A 3:4 L2A 4:1
  • Softmax turns dot products into probabilities: es, then divide by the total. L2A 4:2 L2A 4:4
  • Each word has two vectors (center and outside), 2Vd parameters. L2A 4:3 L2A 4:5
Gradient descent
  • θ←θ−η∂J/∂θ: step downhill on the loss. L2A 5:1 L2A 5:2
  • Limit: one vector per word, whatever the sentence says. L2A 6:1
L2B Language ModelA language model gives a probability to every next token, and so to every sentence.
The chain rule scores a sentence
  • P(w1…wn)=P(w1)P(w2∣w1)⋯ exactly, with no approximation. L2B 2:1 L2B 2:2
n-gram models count
  • Markov assumption: only the last word or two matter. L2B 3:1
  • Bigram estimate: P(b∣a)=count(ab)/count(a). Count pairs, divide, done. L2B 3:2 L2B 3:3
  • Generate by sampling a word, appending it, repeating. L2B 3:4
Where counting breaks
  • An unseen pair gives a whole sentence probability 0. Add-one smoothing: P(b∣a)=(count(ab)+1)/(count(a)+V). L2B 4:1
  • Counting cannot share across similar words; neural models can, through vectors. L2B 4:2 L2B 5:1 L2B 5:2
L3A The Neural NetworkThe forward pass: look up vectors, multiply by matrices, bend, score, softmax, loss.
A layer is a matrix times a vector
  • One dot product per row; rows are outputs, columns are inputs. L3A 3:1 L3A 3:2
  • ReLU keeps positive entries and sets the rest to 0. Which units are switched off depends on the input. L3A 3:3
From scores to a loss
  • Logits → softmax → a probability for every word. L3A 3:4 L3A 3:5
  • Cross-entropy loss is −ln of the true word's probability. L3A 3:6 L3A 3:7
Counting parameters
  • θ is everything training may change, E included; the window n is your choice. L3A 4:1
What the network buys, and its limits
  • It generalizes to contexts never seen, across similar words. L3A 5:1
  • A fixed window cannot look far back, and treats each position separately. L3A 6:1
L3B BackpropagationOne backward sweep gives every weight its slope; every weight steps.
A slope is how much the loss moves
  • Wiggle one weight and measure: correct but far too slow for millions of weights. L3B 2:1 L3B 2:2
The chain rule
  • Slopes multiply along a path and add across paths. L3B 2:3 L3B 2:4
  • At the output, softmax with cross-entropy gives ∂J/∂𝐬=𝐩−𝐲: push too-high scores down, too-low up. L3B 3:1
  • A unit ReLU switched off passes back a slope of 0. L3B 2:4
The update and the training loop
  • θ←θ−η× gradient; the learning rate sets the step. L3B 4:1
  • E receives gradients too, so similar words end up with similar vectors. L3B 5:1
  • Deep stacks multiply many slopes: they vanish or explode. L3B 5:2
  • Batches and epochs: an affordable step versus an accurate one. L3B 6:1 L3B 7:1
L4A AttentionEach word builds its new vector as a weighted sum of the values of the words up to it.
Why attention
  • Recurrent networks forget with distance and must run in order. L4A 1:1 L4A 2:1 L4A 2:2
  • Attention reaches every earlier word in one step, as a weighted average. L4A 3:1 L4A 3:2
Queries, keys and values
  • Query: what a word looks for. Key: how well a word is found. Value: what it adds. Three learned matrices, the same for every word. L4A 3:3 L4A 4:1
  • Score =𝐪·𝐤; higher score, more weight after softmax. L4A 4:2
Mask, scale, output
  • Causal mask: later words get −∞, so weight exactly 0. L4A 4:3
  • Divide by dk so softmax does not put all weight on one word. L4A 4:4
  • Output =∑jαj𝐯j, a sum of values, not of embeddings. L4A 4:5 L4A 4:6
What attention cannot see
  • Word order: "the cat sat" and "cat the sat" give "sat" the same vector. L4A 5:1 L4A 5:2
L4B The TransformerAttention moves information between positions; the feed-forward network computes on each.
Position
  • Add a position vector to each word's vector, so order is in the numbers. L4B 2:1 L4B 2:2 L4B 2:3
Multi-head attention
  • Each head scores with its own part of 𝐪 and 𝐤 and runs its own softmax, so heads can focus on different words. L4B 3:1 L4B 3:2 L4B 3:3
  • Trained heads look at fixed distances back. L4B 3:4
The block
  • Feed-forward network on each position, with GELU. L4B 4:1
  • Residual x + f(x) carries the gradient back. L4B 4:2
  • LayerNorm: mean 0, spread 1 within each vector, then γ and β. L4B 4:3
  • Dropout zeroes random values in training only. L4B 4:4 L4B 4:5
Stack and count
  • A decoder-only model stacks blocks between the embedding and the output layer. L4B 5:1
  • Parameters ≈12Ld2; that decides memory and cost. L4B 5:2
L5A PretrainingNext-token loss over trillions of tokens; scaling laws tell you the shape of the run.
Objective and data
  • The same cross-entropy loss, averaged over every position; nobody labels anything. L5A 1:1
  • Web-scale text, filtered and deduplicated: quality beats volume. L5A 2:1 L5A 2:2
The run
  • A loop over batches: forward, loss, backward, step. L5A 3:1 L5A 3:2
  • Hyperparameters are chosen by you; the learning rate decides whether a run works. L5A 3:3
Scale
  • Compute C≈6ND FLOPs. Divide by a GPU's FLOPs per second for GPU time, then multiply by the price per hour. L5A 4:1 L5A 5:1
  • Scaling laws: loss falls with both parameters and tokens; about 20 tokens per parameter is compute-optimal. L5A 4:2 L5A 4:3
  • For serving, a smaller over-trained model is cheaper. L5A 4:4
Cost
  • Pretrain from zero only for unique data, a badly served domain, or a rule against sending text out. L5A 5:1 L5A 5:2
L5B Post-TrainingThe two cheap stages change behavior, not knowledge.
Supervised fine-tuning
  • Data: request and answer pairs. L5B 1:1 L5B 2:1
  • The loss counts the answer tokens only; the request is masked. L5B 2:2
Learning from preferences
  • Choosing between two answers is cheaper and more consistent than writing one. L5B 3:1
  • RLHF: a reward model plus reinforcement learning; heavy. L5B 3:2
  • DPO: raise the preferred answer and lower the rejected one, each relative to a frozen copy. L5B 3:3 L5B 3:4
L6A PromptingEvery technique changes what the model reads or how the next token is picked; no weight changes.
Examples in the prompt
  • Zero-shot vs few-shot: examples raised accuracy from 72% to 86%. L6A 3:1 L6A 3:2
  • Which examples you pick matters; wrong labels get copied. L6A 3:3
  • Asking for JSON is not a guarantee. L6A 2:1
Decoding
  • Greedy takes the top token. L6A 4:1 L6A 4:2
  • Temperature divides scores before softmax: T < 1 sharpens, T > 1 flattens. L6A 4:3
  • Top-p keeps the smallest top set reaching p; top-k keeps k. L6A 4:4
  • T = 0 when there is one right answer; about 0.7 for writing. APIs default to T = 1, so the same prompt can give different replies. L6A 4:5
  • Constrained decoding sets forbidden tokens to −∞. L6A 4:6
Reasoning
  • One pass per token; writing steps first puts intermediate results in the context. L6A 5:1 L6A 5:2
  • Thinking mode: more right answers, many more tokens. L6A 5:3
L6B Fine-TuningChange the weights once instead of paying for a long prompt on every request.
Methods
  • Full fine-tuning moves every weight: too much memory for a small GPU. L6B 1:2 L6B 2:1
  • Selective and additive methods freeze most of the model. L6B 2:2 L6B 2:3
LoRA
  • 𝐡=W𝐱+BA𝐱: W frozen, A and B small and trained, B starting at 0. L6B 3:1 L6B 3:2
  • Parameters: r(d+k) against dk. Frozen weights cost only their storage. L6B 3:3
Results
  • LoRA matched few-shot accuracy with a quarter of the tokens. L6B 4:1 L6B 4:2 L6B 4:3
  • After training, BA can be merged into W, or kept as a swappable adapter. L6B 4:4
L7A Retrieval-Augmented GenerationRAG changes what the model reads, not what it knows; most of the engineering is in the search.
Why retrieve
  • Closed-book answers invent rules; the whole book does not fit the context. L7A 1:1 L7A 1:4
Chunk
  • Clean the text, then cut it; fixed-size cuts can split a rule. Overlap or cut on structure. L7A 3:1 L7A 3:2
Retrieve
  • An embedding model turns any text, short or long, into one vector of fixed length. L7A 4:1
  • Cosine similarity between the question and every chunk; take the top k. L7A 4:2 L7A 4:3
  • Recall@k and MRR measure retrieval alone. L7A 4:4
  • Chunk size is a trade-off: measure it. L7A 4:5
Generate and diagnose
  • Number the passages and say "use only the passages". L7A 5:1 L7A 5:2
  • Right chunk missing → fix the search. Right chunk present, wrong answer → a generation failure. L7A 5:3 L7A 5:4 L7A 5:5
L8A Agents and Tool UseThe model writes the actions; our code runs them, checks them, and decides how much freedom the model gets.
Why tools
  • A language model's arithmetic only looks right. L8A 1:2
  • Agent: the model chooses an action, a tool runs it, the observation comes back. L8A 1:3
Tools
  • The model sees only the tool's description, never the function. L8A 2:1 L8A 2:2 L8A 2:4
  • MCP standardizes where tools live. L8A 2:5
  • The model only writes the call; our code checks and runs it. A call that fails the check goes back to the model as an error, and the model tries again. L8A 2:6
The loop
  • ReAct: think → act → observe, until it answers or hits a step limit. L8A 3:1 L8A 3:3
  • Failures (select, arguments, validate, stop) each have their own fix. L8A 3:4
Workflow or agent
  • Workflow: our code fixes the steps. Agent: the model decides them. Use the simplest that works. L8A 4:2 L8A 4:3
  • Memory: the message list grows at every step. L8A 5:1 L8A 5:2
L9A SafetyDo not ask the model to keep a rule that matters. Keep the rule in code.
Prompt injection
  • Text from a customer can act as an instruction. L9A 1:2
  • Instructions and data are one token sequence; nothing marks which is which. L9A 2:1
Defenses
  • A system prompt asking the model to ignore it did not stop one attack. L9A 3:1
  • A guardrail in code stopped all of them. L9A 3:2
  • Use several layers, each code or a person. L9A 3:3
L9B EvaluationA score means something only if you know the test set and the rule behind it.
The test set
  • It must look like real input, including questions with no answer. L9B 2:1 L9B 2:4
  • Margin ≈1.96p(1−p)/n: four times the items halve it. L9B 2:2
  • Group errors by slice to find the cause. L9B 2:3
The scoring rule
  • The same replies score differently under different rules. Choose the rule from what the reply is used for, and fix it before you look at the results. L9B 3:1
  • An LLM judge must be checked on replies you have labeled. L9B 3:2
Cost
  • Report tokens and time per query next to accuracy. L9B 4:1
